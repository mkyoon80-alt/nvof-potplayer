NVOF user guide

Smoother video in PotPlayer.
Extract the package, connect the filter, and choose which videos to interpolate.

v0.4.8 · HW/SW switching with integrated graphics
Fixed GPU selection that could stop playback when switching from HW to SW with both integrated and NVIDIA graphics enabled. The trial was confirmed working on an RTX 5080 + AMD integrated-GPU PC.

What you need

  • Windows 10 version 2004 or later, or Windows 11, x64
  • PotPlayer x64
  • An NVIDIA GPU that supports Optical Flow, with its driver installed

Playback has been tested on an RTX 5090; the HW/SW switch fix was also confirmed on an RTX 5080 + AMD integrated-GPU PC. Achievable resolution and output frame rate depend on your GPU and playback settings.

The package includes the filter, controller, and .NET/WPF runtime. VapourSynth, NvOFFRUC.dll, and a separate CUDA runtime are not required. Install PotPlayer and your NVIDIA driver separately.

The controller currently uses Korean labels.
This guide includes the exact Korean labels beside their English meanings so you can follow the same screens. An English program UI is not included in this release.

Extract and register

Download NvofPotPlayer-0.4.8-win-x64.zip from the v0.4.8 release.

  1. Extract to a permanent folder

    Keep the executable, filter, and runtime files together. You do not need to install .NET separately. Before replacing an existing copy, close PotPlayer and the controller and back up your settings.

  2. Register the filter

    Run NvofControl.exe. Open 연결 설정 (Connection settings), then click 필터 등록 (Register filter). Standard, non-administrator PotPlayer uses registration for the current Windows user.

  3. Connect the filter in PotPlayer

    Follow the next section to add the filter to PotPlayer. 현재 폴더 열기 (Open current folder) shows where this copy is stored.

Executables are not code-signed. This ZIP does not install PotPlayer or the GPU driver.

Connect PotPlayer

Registration makes the filter available to Windows. You must also add it to PotPlayer's preferred filter list. This is normally a one-time setup.

  1. Open the filter list

    Press F5 in PotPlayer. Under Filter Control (코덱/필터), open Global Filter Priority (전역 필터 우선 순위). Labels may vary with your PotPlayer language.

  2. Add the NVOF filter

    Choose Add System Codec (시스템 코덱 추가), add NVIDIA Optical Flow for PotPlayer, enable its checkbox, and select Prefer (최우선 사용).

  3. Disable other interpolation filters

    Do not enable another frame interpolation filter at the same time, such as a VapourSynth-based filter or Bluesky Frame Rate Converter.

  4. Continue to hardware decoding setup

    After adding the filter, complete the hardware decoding steps below. To open the NVOF controller, double-click the registered filter and choose 설정 창 열기 (Open settings), or run NvofControl.exe from the extracted folder.

What if PotPlayer runs as administrator?

Running PotPlayer with standard user permissions is the simplest setup. If administrator mode is necessary, use the registration flow in 연결 설정 to register for administrator playback. Windows will request elevation. Unregistering that registration also requires Windows approval.

Decoding and video output

Complete this after connecting the filter, before first playback. This configuration uses PotPlayer's built-in decoder and D3D11 renderer to pass frames directly in GPU memory. Use it when hardware decoding is available. Native DXVA is not required. Software-decoded NV12 SDR and supported 10-bit formats can use the CPU-to-GPU path. The DXVA options below are recommended when using hardware decoding; use the built-in D3D11 renderer for either path.

  1. Open the built-in video decoder settings

    Press F5 in PotPlayer, then open Filter Control → Video Decoder → Built-in codec/DXVA settings (코덱/필터 → 비디오 코덱 → 내장 코덱/DXVA 설정).

Set these options in PotPlayer itself. Registering the NVOF filter does not change PotPlayer's decoder or renderer settings.

Interlaced video: disable PotPlayer deinterlacing

Use this setting when interpolating software-decoded interlaced video, such as 1080i 10-bit footage, with NVOF.

Right-click the video → Video → Deinterlacing → Do not use
Korean labels: 영상 → 디인터레이스 → 사용하지 않음. Reopen the video afterward. NVOF receives the original fields, deinterlaces them on the GPU, and then interpolates.

Why turn it off?

The odd and even lines of interlaced footage represent different moments in time. If PotPlayer blends these lines into one picture first, moving edges can overlap and some motion information can be lost. This makes motion estimation harder for NVOF and can produce uneven interpolation.

Disabling PotPlayer's deinterlacing lets NVOF process the original fields in their temporal order. Deinterlacing is handled by NVOF rather than skipped.

How does this affect frame rate?

A 25fps interlaced source containing 50 field moments per second is reconstructed as 50p before interpolation. A 120fps cap then gives 100fps (50 ×2). This differs from applying ×4 to ordinary progressive 25p input.

This guidance applies to the supported CPU-decoded 10-bit interlaced path. Ordinary progressive video does not need deinterlacing. When playing interlaced video with NVOF disabled, restore PotPlayer to Automatic (자동 판단).

Interpolation settings

Turn on 프레임 보간 (Frame interpolation), then use 보간 설정 (Interpolation settings) to choose videos and output. Reopen the video after changing settings.

Source FPS
보간할 원본 FPS

Select 24 / 25 / 30 / 50 / 60 / 기타 (Other). Rates of 23.976, 29.97, and 59.94fps belong to the 24, 30, and 60 groups. Unchecked groups play at their original frame rate.

Vertical resolution
세로 해상도

Choose 전체 (All), 1080p 이하 (Up to 1080p), or 1440p 이하 (Up to 1440p). Videos taller than the selected limit play at their original frame rate. The condition uses the video's pixel height, not the player window or monitor resolution. For example, Up to 1080p includes 1920×1080 and excludes 3840×2160.

FPS cap
FPS 상한

Under 출력 방식 (Output mode), choose FPS 상한, then select 60 / 72 / 75 / 100 / 120 / 144 / 240fps. The filter uses the largest integer multiple within the cap. The default is 60fps. If even ×2 would exceed the cap, the video stays at its original rate. Sources already above the cap are not slowed down.

Source multiplier
원본 배수

Choose 원본 배수, then select ×2 / ×3 / ×4 / ×5. The saved FPS cap does not apply in this mode. Both modes remember their last selection independently. Source FPS and height conditions apply to both.

A 60fps cap does not convert every video to exactly 60fps.
A 24fps source becomes 48fps with a 60fps cap. Choose a 72fps cap or source ×3 for 72fps.

The cap calculation allows a 0.1% tolerance for small source-rate deviations. A 30.003fps video can therefore use ×2 at a 60fps cap (60.006fps), or ×4 at a 120fps cap (120.012fps), without changing its playback duration.

Do ×3 and ×5 generate different intermediate frames?

Yes. ×3 generates frames at one-third and two-thirds of the interval between two originals. ×5 uses 20%, 40%, 60%, and 80%. These are individually synthesized frames, not repeated copies of one midpoint. Higher output rates require more processing; check the actual rendering rate and dropped frames in PotPlayer.

10-bit SDR and HDR video

Starting HDR in SW or switching from HW to SW
v0.4.7 requests P010 from a supporting decoder. After switching, check actual P010 · 10bit input/output and HDR10 / HLG in Diagnostics. It cannot restore precision from 8-bit NV12. Dolby metadata is forwarded only when supplied by the decoder; an HDR10 label does not establish Dolby Vision display output.

Bit depth and HDR are separate properties: 10-bit H.264 can be SDR. In 진단 (Diagnostics), check the input format, P010 · 10bit output, and SDR / HDR10 / HLG signal type.

Input processing
InputProcessing and output
8-bit SDR · NV128-bit NV12 output. Software-decoded input is uploaded for GPU interpolation and delivered as GPU surfaces to a compatible D3D11 renderer.
GPU decoding · P010Original and generated frames remain 10-bit in GPU memory.
CPU decoding · 10-bitP010 / P016 / P210 / Y210 samples are uploaded for GPU conversion and interpolation, with P010 output. PotPlayer may show S/W while interpolation still runs on the GPU.
HDR10 · BT.2020 PQPreserves P010, color signaling, and supplied static HDR metadata. Missing HDR signaling can now be recovered from VP9 configuration as well as HEVC and AV1.
HLG · BT.2020Preserves P010 and HLG color signaling.

Use native D3D11 decoding when the codec is hardware-supported. Supported software-decoded NV12 SDR and 10-bit formats can also feed GPU interpolation. This does not add hardware codec support. The built-in D3D11 renderer and an NVIDIA GPU are still required. For interlaced input, also follow the deinterlacing instructions.

A 10-bit source does not guarantee 10-bit decoder output.
If the decoder sends NV12, NVOF receives 8-bit samples and cannot restore the lost precision. Check the actual input and output formats in Diagnostics. PotPlayer’s NV12(12 bit) label does not mean 12-bit color precision.

Are both 10-bit precision and 4:2:2 preserved?

Output is 10-bit 4:2:0 P010. P210/Y210 chroma is reduced from 4:2:2 on the GPU. If the decoder already outputs P010, chroma detail lost upstream cannot be recovered. P016 uses its upper ten bits; this is not a 16-bit preservation path.

What does Dolby Vision support mean here?

The filter forwards decoder-supplied Dolby Vision RPU and parsed metadata. Original frames retain their own metadata; generated frames inherit the preceding original's metadata. Actual metadata transport was verified with a Profile 8.1 source.

Decoding, reshaping, tone mapping, and display output remain the decoder's and renderer's responsibility. This does not certify every Dolby Vision profile or Dolby Vision display output. An HDR10-compatible base layer may still appear as HDR10 in Diagnostics. HDR10+ dynamic metadata is unsupported.

Normal colors were confirmed in actual playback of HDR10 files and YouTube AV1/VP9 HDR. HEVC HLG playback and signal transport were verified; a separate visual color comparison remains unverified. The filter does not tone-map or switch the monitor into HDR mode.

Optional VSR

After completing hardware decoding setup, you can optionally enable PotPlayer's GPU Super Resolution.

Built-in decoder→NVOF interpolation→Renderer / VSR→Display

VSR also uses GPU resources. If frames drop at a high output rate, compare playback with VSR disabled.

Verify playback

  1. Reopen an eligible video

    For example, enable the 24 source group for a 23.976fps video. Its height must also meet your selected condition.

  2. Check the controller's current status

    프레임 보간 동작 중 means interpolation is active. A rate such as 23.976 → 47.952fps shows the current conversion. An enabled switch alone does not prove the filter is interpolating. 마지막 재생 상태 refers to the previous playback status.

  3. Check Diagnostics

    Open 진단. GPU 메모리로 직접 전달 reports the filter's GPU transport. This can also follow CPU decoding and upload, so check the decoder in PotPlayer's playback information separately. For CPU-decoded 10-bit video, verify P010 output and the interpolation rate. Use PotPlayer's Tab playback information to check actual rendering FPS and dropped frames.

  4. Try seeking and closing

    Seek forward and backward. The filter discards interpolation history from the previous position and restarts from the new source frames. Check that playback and shutdown work normally.

The filter does not draw its own FPS or startup overlay onto the video. PotPlayer playback information and VSR indicators are controlled separately.

Troubleshooting

Start with the matching symptom and change one setting at a time.

HDR video is too bright in SDR mode, or tone-mapping controls have no effect

When viewing PQ HDR video with Windows and the monitor in SDR mode, compare these settings first.

  1. Under Preferences → Video, turn off Use H/W HDR output mode (Korean UI: D3D11 HDR 출력을 H/W로 처리).
  2. Under Video → Pixel Shader, enable SMPTE ST 2084 HDR Correction.
  3. Start with Auto tone mapping and 125 nits SDR monitor luminance, then compare the same scene. ST 2086 correction was not needed for this check.

In the local Dune comparison, bright detail was lost even with NVOF excluded. Switching HW/SW decoding or changing the tone-mapping curve and SDR luminance had no visible effect. Turning off H/W HDR output made those controls responsive, and the user confirmed that bright detail returned with Auto and 125 nits unchanged.

H/W HDR output and hardware decoding are separate settings. Hardware decoding and GPU interpolation can remain enabled. The 125-nit value is a comparison starting point, not a measurement of the monitor. This guidance is for SDR viewing; do not apply it indiscriminately to actual HDR display output.

HW-to-SW switching stops playback with integrated graphics enabled

v0.4.8 validates the renderer’s GPU index and retains the NVIDIA GPU already in use. Software startup also handles invalid GPU hints. You do not need to disable integrated graphics or change GPU settings for this fix.

  1. Close PotPlayer and the NVOF controller, then back up the installation folder.
  2. Replace the files with v0.4.8 while preserving NvofPotPlayer.ini.
  3. Reopen the same video and check HW/SW switching and a fresh SW start.

The trial was confirmed on an RTX 5080 + AMD integrated-GPU PC; this does not verify every multi-GPU configuration. If playback still stops, collect the GPU configuration, switching sequence, and NVOF diagnostic logs.

Drops with Low Latency Mode or high output rates

v0.4.7 improves shared GPU locking, completion waits, and output buffering. Foreground HW playback at 240fps with Low Latency Mode On was confirmed on an RTX 5090. Turning Low Latency Mode off is not a requirement.

Check whether Max Frame Rate or Background Application Max Frame Rate in the NVIDIA PotPlayer program profile limits output. Compare foreground and background playback separately. A 165Hz display cannot show all 240 distinct frames per second. Compare a rate within the display refresh, and distinguish continuous-playback drops from seek/resume transitions. Real-time 4K at 240fps is not guaranteed on every GPU.

Broken reticles, hair, or object boundaries

v0.4.7 protects thin stationary horizontal and vertical strokes to reduce reticle splitting. It cannot identify every line or moving object. Occlusion artifacts such as the Lupin gun boundary remain unresolved. No general blur or whole-frame hold is introduced.

The filter is missing or settings will not open
  1. Check that PotPlayer is x64.
  2. Use Register filter (필터 등록) from the current extracted folder.
  3. Fully close and restart PotPlayer.
  4. Administrator-mode PotPlayer requires administrator registration.
The switch is on, but interpolation is inactive

Check PotPlayer's filter checkbox and Prefer setting, the selected source FPS groups, and the height condition. Reopen the video. If an FPS cap allows only ×1, playback stays at the source rate. Diagnostics shows the bypass reason. For 10-bit video, check P010 output and the built-in D3D11 renderer. Software decoding is also supported for the listed formats.

HW-to-SW switching works, but starting in SW mode does not

v0.4.6 fixed GPU output being prepared too late for the first software-decoded connection. It also includes the earlier HW/SW switching freeze fix.

  1. Fully close PotPlayer and the NVOF controller, then update to v0.4.8. Keep your existing NvofPotPlayer.ini.
  2. Select the built-in D3D11 renderer and reopen the video with hardware decoding disabled. You do not need to enable HW first.
  3. Check that NVOF appears in the active filter list and that the controller reports active interpolation and an output frame rate.

S/W indicates CPU decoding. It can remain visible while interpolation runs on the GPU.

10-bit video is black or playback stops

Update to v0.4.8, then fully close and reopen PotPlayer. Use the built-in decoder and D3D11 renderer. Check for P010 input and output in Diagnostics. If the issue persists, compare an 8-bit SDR video and report the GPU, driver, diagnostics, and reproduction steps.

PotPlayer briefly shows S/W before H/W

Labels can change while the filter graph connects and initializes. Once playback stabilizes, check the transport path and output rate in Diagnostics.

Edges break up or movement stutters

For interlaced sources, first check the deinterlacing setup. Disable other interpolation filters. Compare the same scene with NVOF off and on, reopening the video each time. Try a lower multiplier or another cap. Report the timestamp, source FPS and resolution, GPU/driver, and whether VSR was enabled.

4K playback cannot maintain the selected rate

Distinguish drops immediately after seeking or resuming from drops during uninterrupted playback. The controller’s output rate is the target, not proof of the display rate. Check the actual rendering FPS and dropped frames in PotPlayer. Decoding, interpolation, rendering, and VSR all contribute to the load. Try a lower multiplier or turn VSR off for comparison. To exclude 4K videos, select Up to 1080p or Up to 1440p under Vertical resolution.

HDR looks washed out or the color is wrong

Missing HDR signaling is recovered for supported HEVC, AV1, and now VP9 streams. Check the built-in D3D11 renderer and look for P010 · 10bit and HDR10 or HLG in Diagnostics. Compare the same scene with the filter disabled. Remember that signal information in the filter does not confirm the display's HDR mode.

HDR looks red, oversaturated, or too bright

Compare the same scene while checking Windows HDR, player HDR output/tone mapping, and the monitor’s HDR/SDR picture mode, color temperature, and saturation. ST 2084 correction for SDR viewing is an HDR-to-SDR display setting, separate from preserving 10-bit frames. Record existing values and change one setting at a time.

  1. Compare windowed and fullscreen playback information (Tab).
  2. Exclude NVOF through Global Filter Priority and reopen the video. Disabling interpolation alone may leave the filter connected.
  3. If the appearance is unchanged without the filter, compare player, driver, and monitor display settings first. The local SDR-viewing overbrightness report was resolved through the HDR output setting. Compare other color symptoms separately.

This does not identify the cause of every HDR report. HDR screenshots alone do not establish the monitor’s actual color or luminance. This release does not claim an oversaturation fix.

Update or removal is blocked

Close PotPlayer and the controller before replacing files. For removal, first close PotPlayer, unregister through the controller, then close the controller and delete the standalone folder. Administrator registration requires Windows approval to unregister.

What information helps with a bug report?

Include NVOF diagnostics, GPU and driver version, source resolution/FPS/color type, the affected timestamp, and reproduction steps. Logs are stored in %LOCALAPPDATA%\NvofPotPlayer. Check for personal file paths before sharing. The program does not automatically upload diagnostics.

Update, move, or remove

Update a standalone copy

Close PotPlayer and the controller, then back up the existing folder. Replace the program files at the same location, keeping your existing NvofPotPlayer.ini. Older 60/120fps choices are preserved.

Move or remove

Close PotPlayer. Open 연결 설정 (Connection settings) and click 필터 등록 해제 (Unregister filter). This removes current-user and administrator registrations owned by this folder. Administrator registration requires Windows approval; cancelling does not count as successful removal.

After success, close the controller and move or delete the folder. If you moved it, register again from the new location. Unregistering does not delete files or remove registrations owned by another folder.

Switch from an installer version

For older installer releases such as v0.3.0, back up NvofPotPlayer.ini and close PotPlayer and the controller. Remove the old version through Windows Installed apps, approving elevation if required. Extract the new ZIP into a separate folder, restore your settings as needed, register the filter, and check PotPlayer's filter priority.

프로그램 제거 (Uninstall program) appears only when the controller finds a matching installer uninstaller in its own folder. It is not shown for the standalone ZIP.

Support and component notices

Testing used Windows 10 x64, an RTX 5090, and PotPlayer's built-in decoder and D3D11 renderer. The supported color range is limited-range BT.709 SDR and BT.2020 PQ/HLG. CPU NV12 SDR startup with HW decoding off, HW/SW switching, progressive 10-bit input, and 1080i interlaced input were tested. This is not a guarantee for every interlaced format, telecine, or multi-GPU setup.

Hair, smoke, and overlapping motion can still show artifacts. Selecting a high output rate does not guarantee real-time 4K playback on every GPU. The latest post-seek combing fix passed reproduction tests; additional actual-player confirmation remains pending.

The package includes the filter, registration helper, controller, and .NET/WPF runtime. It does not bundle FRUC/CUDA runtimes, NVIDIA drivers, or PotPlayer.
