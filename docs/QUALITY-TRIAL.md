# 0.3.1-quality.1 — 경계 보완 시험

이전 설치판 opt.1을 기준으로 Jishou 4화 5:20–5:23과 F1 1:32 부근의 잔여 깨짐을 재현했다. F1의 흰 글자·코스 선 주변 조각은 일부 줄었고, Jishou의 개선 폭은 작다. 머리카락 바깥쪽 잔상과 고정 선 뒤 인물의 왜곡은 남아 있다. 두 구간을 완전히 해결했다거나 플루이드 모션을 능가했다는 결과가 아니다.

사용자 비교 결과: 플루이드 모션은 F1 글자를 완벽하게 처리했고, Jishou는 완벽하지 않지만 조금 나았다. 이 관찰은 후속 비교 기준이며 이번 자동 검증의 기준 영상으로 사용한 것은 아니다.

## 변경

- 분석 해상도의 역좌표를 원본 크기로 확대할 때, 인접 좌표의 차이가 2픽셀보다 크면 각각의 원본 색을 읽어 혼합한다. 서로 다른 움직임의 좌표를 먼저 평균내어 관계없는 세 번째 위치를 읽는 오류를 줄인다. 연속적인 영역은 기존 좌표 보간을 사용한다. 경계의 작은 혼합 구간은 약간 부드러워질 수 있다.
- 정지 글자의 밝기 대비가 배경 움직임 때문에 변해도, 정규화한 경계 모양과 위치가 일치하면 정지 증거를 유지한다. 원본 간 일치·주변 움직임 비교·가장자리 위치 검사는 유지한다.
- 양방향 Newton 결과가 모두 약하고 서로 다른 색을 가리킬 때만 주변의 검증된 움직임을 후보로 시험한다. 앞뒤 원본의 작은 영역 오차가 절반 이하로 낮아지고 절대 오차도 작으며, 적어도 한쪽 실제 끝점이 해당 움직임을 뒷받침해야 채택한다. 고정 글자 영역은 제외한다. 복구한 후보에 하드웨어 Cost를 잘못 귀속시키지 않는다.

단순히 주변 후보를 많이 찾는 방법과 더 넓은 보정은 일부 장면에서 도움이 됐지만 다른 움직이는 글자를 악화시켜 채택하지 않았다. 원본 반복으로 깨짐을 감추는 변경은 하지 않았다.

Newton 최대 6회·backtracking, ×2 출력, Grid 4·Medium·최대 긴 변 1920 분석을 유지한다. NVOFA 세션·6개 공유 입력 버퍼 재사용을 유지하며 Temporal Hints와 Cost Map 생성·적용은 꺼져 있다. CPU/GPU 동기화와 탐색 시 초기화 정책도 유지한다.

## 검증 방법

RTX 5090, 드라이버 617.42. 디코딩과 화면 표시는 제외한 GPU 완료까지의 처리 시간을 측정한다. RTX 5070 성능이나 전체 플레이어 FPS 측정이 아니다.

- `native_motion_sampling`: 별개의 두 역좌표 사이에만 밝은 줄을 둔 합성 입력으로, 좌표 평균 때문에 존재하지 않는 줄이 나타나는지 검사한다. 2배 해상도·세 시점 및 연속 영역의 소수 픽셀 이동을 함께 확인한다. WARP에서도 실행 가능하다.
- 기존 여섯 합성 움직임 장면과 실제 영상 10구간을 이전 실행 파일과 비교한다. 실제 영상의 모든 원본 출력·시간·장면 판단·원본 반복 횟수는 동일해야 한다.
- 실제 영상 중 F1 1:30·2:10 비교는 원본을 한 장씩 제외하고 복원한 뒤, 제외한 진짜 프레임과 비교한다. 일반 ×2 출력에는 정답 중간 영상이 없으므로 원본 평균과의 차이를 화질 점수로 사용하지 않는다.
- 대상 두 구간도 별도로 프레임 제외 비교를 수행한다. 이 비교는 정상 재생보다 움직임 간격이 두 배이며, Jishou는 기존 보호 로직이 71쌍 중 27쌍을 반복 출력한다. 작은 전체 평균 차이를 체감 개선율로 해석하지 않는다.
- 필터 CPU/NV12·GPU/P010 연결, flush/stop·탐색, 세션 재사용, 방향 반전, 원본 보존을 검사한다.

재현:

```powershell
python tools/compare-quality-trial.py --baseline build/opt1/native/Release/video_x2_repro.exe --candidate build/quality1/native/Release/video_x2_repro.exe --output build/quality-comparison
```

원본 영상·캡처·시험 산출물은 저장소에 포함하지 않는다. 비교 도구는 새 build 폴더의 임시 출력만 지우고, 선택한 프레임과 결과를 남긴다. 전체 검증 기록은 로컬 `build/quality1`에 있다.

## 2026-10-10 최종 결과

- 실제 영상 10구간: 774개 입력 쌍 / 1,568개 출력 프레임. 원본 출력의 모든 바이트, 타임스탬프, 장면 전환·원본 반복 판단이 opt.1과 일치했다. Cost 버퍼는 0개였다.
- 첫 5쌍을 제외한 구간별 평균 처리 시간은 opt.1 대비 -0.76%~+1.94%였다. Jishou 5:20–5:23은 2.756→2.796ms, F1 글자는 2.330→2.330ms였다. 단일 비교 실행의 편차를 포함하며 전체 플레이어 성능 측정은 아니다.
- F1 기존 문제 구간의 프레임 제외 비교: 1:30 전체 휘도 MSE 32.974→32.243, 2:10은 94.250→94.002였다. 경계 부드러움도 바뀌므로 오차 감소율을 체감 개선율로 보지 않는다.
- 대상 구간의 별도 프레임 제외 비교: F1 글자 전체 MSE 178.103→177.596, Jishou는 491.345→491.220으로 변화가 작았다. Jishou 관심 영역의 경계 오차는 138.771→138.929로 조금 증가했다. Jishou의 전반적인 품질 개선을 수치로 확정할 수 없다.
- 새 좌표 혼합 회귀 검사는 이전 셰이더에서 예상대로 실패하고 이번 셰이더에서 통과했다. 기본 CTest 7개, 합성 6장면, CPU/GPU/P010 연결, 탐색·동시 flush/stop, GPU 스트레스 검사가 통과했다.
- 세션 재사용 비교는 128쌍에서 원시 흐름과 합성 출력 모두 새 세션 방식과 같았다. 방향 반전·100회 초기화·유지 중인 출력 검사도 통과했다.

선택한 F1·Jishou·Kokoore 비교 프레임은 마지막 재빌드 전후 동일했다. 재현 로그와 선택 프레임은 `build/quality1/regression-final`, 별도 제외 프레임 비교는 `build/quality1/holdout`에 보존한다. 최종 설치와 복원 경로는 로컬 `build/quality1/installation.json`에 기록한다.
