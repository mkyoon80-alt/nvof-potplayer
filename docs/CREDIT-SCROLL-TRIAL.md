# 0.3.1-credits.3 — 배경과 분리한 글자 이동 검사

credits.2 이후 F1 2:29:08·18·21에서 크레딧이 심하게 깨진다는 보고를 받았다. 마지막 장면은 눈으로 검게 보여 움직이는 바다 배경만으로 문제를 설명할 수 없었다. 각 구간의 정상 프레임 쌍을 추출해 검사한 결과, 이전 글자 이동 지도에는 유효 모델이 세 장면 모두 0개였다. 특정 영상 검정(16±3)과 영역 전체의 중성 색을 요구하던 조건이 바다 위 글자뿐 아니라 검정에 가까운 페이드도 제외했다. 종전 2:28 구간만으로 한 검증의 범위가 부족했다.

## 변경

- 기존 검은 바탕 검사에 더해 **흰 중성 획 자체**의 특징을 비교한다. 배경 밝기·색은 이동 오차 계산에서 분리한다. 17×17 표본의 어두운 부분 비율, 밝은 획의 개수·폭을 검사하고 주변 광학흐름으로 제안한 이동을 두 원본의 획 모양으로 검증한다.
- 새 특징 오차는 0~255로 정규화한 값이다. 최종 오차 20 이하이면서 제자리 비교 오차의 35% 이하만 인정한다. 기존 검은 바탕 경로의 밝기 오차 한계 10과는 서로 다른 척도다. 가는 글자는 적은 표본으로 이동을 제안할 수 있지만 **서로 가까운 모델 세 곳 이상이 일치**해야 실제 합성에 쓴다. 서로 충돌하는 이동은 사용하지 않는다.
- 주변 4×4 모델을 확인해 글자 사이의 작은 검사 공백을 연결한다. 새 경로의 적용은 실제 글자 획과 잘못 가져온 글자 흔적에 제한한다. 원래 위치로 돌아가는 합성, 네 개의 역좌표 가지에서 글자가 묻어 나오는 경우를 함께 확인한다. 그 밖의 배경은 Newton 출력을 유지한다.
- 특정 영화·시간·좌우 위치를 지정한 분기는 없다. OCR이나 모든 종류의 자막 인식 기능은 아니다. 색 글자, 밝은 배경, 반투명 획, 빠르거나 서로 겹치는 이동, 프레임 끝부분에는 한계가 있다. 가는 획 주변의 작은 흔적도 남는다.
- 새 CPU 읽기·GPU 대기·버퍼·프레임 이력은 추가하지 않는다. 셰이더는 사전 컴파일한다. ×2, Grid 4, Medium, 긴 변 최대 1920 분석, Newton, 세션 재사용을 유지한다. Cost Map·Temporal Hints는 계속 꺼져 있다.

## 실제 영상 확인

RTX 5090 / 드라이버 617.42. 최종 셰이더 헤더의 SHA256은 품질 검사 때와 버전 표기 변경 후 빌드에서 동일했다.

새 세 구간은 각각 원본 72장/71쌍으로 검사했다. 원본 출력과 시간은 동일하며 반복 판단을 늘리지 않았다. 등속 이동을 가정한 밝은 획 진단 오차는 바다 9.338→3.613, 페이드 7.326→1.551, 검은 배경 4.871→1.204였다. 이는 정답 영상 대비 화질 점수나 전체 화질 개선율이 아니다. 선택한 여러 시점의 확대 비교에서 큰 세로 찢어짐은 줄었지만 일부 획 가장자리에는 흔적이 남는다.

원본을 한 장씩 제외하고 실제 빠진 프레임과 비교한 별도 검사도 각 35쌍씩 수행했다. 아래의 글자 영역은 실제 중간 원본의 밝은 획과 주변 3픽셀, 배경 영역은 그 획에서 15픽셀 이상 떨어진 곳이다. 정상 재생보다 시간 간격이 두 배이므로 결과를 정상 재생의 개선율로 해석하면 안 된다.

기존 실제 영상 10구간 774쌍/출력 1,568장의 원본·시간·장면 전환·반복 판단은 동일했다. 8개 구간은 합성 출력도 credits.2와 바이트 단위로 동일했다. Kokoore 1:20, Jishou 4화 5:20대·23:24, F1 1:32·1:30·2:10 등이 포함된다. Jishou 5화 머리카락 구간은 전체 비교에서 4,065개 Y/UV 표본(최대 12/255), F1 1:24는 501개 표본(최대 4/255)이 달랐다. 모든 영상이 무변경이라는 보장은 하지 않는다.

늦은 2:28 크레딧에서 구버전→후보→후보→구버전 순서로 측정했다. 첫 5쌍과 반복을 제외한 각 184쌍 평균은 3.0155→3.1944ms, 약 +0.179ms/+5.9%였다. 디코딩·화면 표시는 제외하며 RTX 5070 성능을 의미하지 않는다.

WARP 검사에 검정 밝기가 16이 아닌 장면, 배경 페이드, 움직이는 유색 배경 위 중성 글자, 배경이 움직여도 고정된 글자의 거부를 추가했다. 최종 합성 검사에서는 알려진 중간 글자 위치 복원, 글자에서 떨어진 배경 출력 보존, 고립된 모델·서로 충돌하는 모델의 거부를 확인한다.

추가로 2:28:44부터 95쌍, 2:28:47부터 191쌍도 비교했다. 등속 이동 진단값은 각각 3.9823→3.9863, 4.0424→4.0583으로 거의 같지만 조금 증가했다. 이 두 구간까지 모두 개선됐다고 해석하지 않는다. 원본·시간은 동일했다. 첫 구간의 오른쪽 영상은 같았고, 늦은 구간에서는 오른쪽 범위의 Y/UV 표본 5,171개가 달라졌다. 선택한 확대 프레임과 다른 장면의 최대 변화 위치를 검토했으며 모든 출력이 불변이라고 주장하지 않는다.

최종 CTest 9개와 CPU 전송, 합성 6장면/3시점, 모호한 흐림 보호, CPU·GPU·P010 DirectShow 연결, 탐색·동시 flush/stop, 100회 초기화 GPU 스트레스, 시작 검사를 통과했다. 마지막 스트레스는 347쌍·100회 reset으로 완료됐고 사전 컴파일 경로의 초기화 시간은 약 1.9ms였다. 팟플레이어 전체 재생 시작 시간이나 실제 표시 품질을 대신하는 수치는 아니다.

원본·캡처는 저장소나 패키지에 포함하지 않는다. build/credits3에 검사 결과, 선택한 원본/비교 프레임, 재현 스크립트와 설치 기록을 보존한다. 아래는 이전 시험 당시의 설명으로 현재 결과와 구분한다.

# 0.3.1-credits.2 — 검증된 글자 묶음의 공통 이동

credits.1 이후 사용자가 F1 2:28:48·53에서 여러 줄의 글자가 여전히 세로로 찢어진다고 보고했다. 큰 줄 착오만 교정해서는 작은 이동 오차와 글자 내부의 급격한 흐름 변화가 남았다. 이번 시험은 픽셀별 Newton 합성을 기본으로 유지하면서, 검은 바탕의 밝은 글자가 함께 평행 이동하는 것으로 확인되는 영역에 별도 합성 경로를 적용한다.

## 동작과 범위

- 분석 좌표 32픽셀 간격의 겹치는 영역마다 17×17개 원본 표본을 검사한다. 289개 중 어두운 표본 160개 이상, 밝은 표본 8개 이상, 어두운 표본 중 영상 검정(16±3)에 가까운 비율 85% 이상, 중성 색을 요구한다.
- 주변 광학흐름 17개 위치에서 공통 이동 후보를 얻고 글자 획의 영상 오차로 검증한다. 분석 픽셀 기준 1~16 범위의 이동만 후보로 쓰며 4단계의 2차원 세부 탐색으로 소수 픽셀 이동을 보정한다. 고정 글자는 제외한다.
- 최종 획 오차가 10 이하이면서 이동하지 않았을 때의 35% 이하이어야 한다. 인접 영역의 이동이 서로 충돌하거나 실제로 가져올 원본 색·밝기가 맞지 않으면 기존 Newton 합성을 사용한다. 검증된 영역에서는 앞·뒤 원본을 각각 중간 시점까지 이동해 합성한다. 프레임 반복이나 재생 속도 변경으로 오류를 숨기지 않는다.
- 32개 GPU 스레드가 한 묶음을 담당해 원본 표본을 공유하고 이동 후보를 동시에 검사한다. 작은 이동 지도는 세션과 함께 재사용하며 매 프레임 쌍 전체를 다시 쓴다. 새 CPU 읽기·GPU 완료 대기·프레임별 버퍼 할당은 추가하지 않는다. 셰이더는 빌드 시 사전 컴파일한다.
- 파일명·시간·화면 좌우 위치에 따른 분기는 없다. 검은 바탕의 밝은 중성 글자에 제한된 보완이며 일반적인 OCR이 아니다. 유색 글자, 밝은 배경, 너무 빠른 이동, 복잡하게 겹치는 내용, 프레임 가장자리에는 적용되지 않거나 잔여 깨짐이 남을 수 있다.

## 검증

RTX 5090 / 드라이버 617.42, ×2·Grid 4·Medium·최대 긴 변 1920 분석. Cost Map·Temporal Hints는 계속 꺼져 있다.

- F1 2:28:47부터 원본 192장/191쌍을 비교했다. 2:28:53을 포함한 이름·역할명의 줄 섞임이 시각적으로 크게 줄었다. 원본 192장과 출력 시간은 그대로이며 오른쪽 실사 영상 영역은 바이트 단위로 동일했다. 반복 판단도 동일했다.
- 등속 스크롤을 가정한 밝은 획 진단 오차는 9.568→5.657이었다. 이 값은 정답 영상 대비 화질 점수가 아니며 전체 화질 개선율로 해석하면 안 된다.
- 원본을 한 장씩 제외한 95쌍에서 실제 제외한 원본과 비교했다. 크레딧 영역 MAE는 1.40282→1.27405, MSE는 90.5673→79.6772로 감소했다. 시간 간격이 두 배인 별도 조건이며 정상 재생의 모든 프레임을 보증하지 않는다.
- 기존 실제 영상 10구간 774쌍/출력 1,568장의 합성 출력까지 credits.1과 바이트 단위로 동일했다. Kokoore 1:20, Jishou 머리카락·5:20대, F1 1:32·1:24·1:30·2:10을 포함한다. 이는 해당 시험 범위에서 다른 영상의 변경이 없었다는 결과다.
- 정상 간격 늦은 크레딧을 구버전→후보→후보→구버전 순서로 측정했다. 첫 5쌍과 반복을 제외한 각 184쌍의 평균을 합치면 2.8839→3.0474ms, 약 +0.164ms/+5.7%였다. 디코딩·화면 표시는 제외하며 5070 성능을 의미하지 않는다.
- WARP 검사에 공통 이동, 소수 픽셀 이동, 잘못된 행 이동, 고정 글자·빠른 스크롤·무늬 없는 검정·유색 내용·서로 반대인 두 이동의 거부를 추가했다. CTest 9개, 합성 6장면/3시점, CPU·GPU·P010 연결, 탐색/동시 flush·stop, 100회 초기화 GPU 스트레스, 시작 검사를 통과했다.

원본·캡처는 저장소와 배포 패키지에 포함하지 않는다. 로컬 build/credits2에 검사 스크립트, 수치, 선택한 비교 프레임과 이전 버전으로 돌아갈 설치 기록을 남긴다. 아래는 이전 시험의 당시 결과이며 현재 버전의 설명과 구분한다.

# 0.3.1-credits.1 — 스크롤 크레딧

사용자가 overlay.1에서 F1 1:32가 많이 좋아졌다고 확인한 뒤, 2:28:46 크레딧의 글자 섞임을 보고했다. 2:28:44부터 96개 원본 프레임을 추출해 95쌍을 검사했다. 원본의 왼쪽 크레딧 이동은 약 -8.23픽셀/프레임인데 일부 광학흐름은 약 -60픽셀로 다른 줄을 가리켰다. 종전 일반 흐름 교정은 4K에서 64픽셀보다 큰 움직임에 한정돼 이 경우를 놓쳤다.

## 변경

- 분석 픽셀 기준 길이 8 초과~32 이하의 모호한 움직임에서, 9×7 표본으로 검은 바탕·밝은 글자·중성 색을 검사한다. 검은 표본의 70% 이상이 제한 범위 영상의 검정(16±3)에 가까워야 한다. 압축 잡음은 일부 허용하지만 어두운 실사 배경은 보수적으로 제외한다.
- 글자/배경 중 실제 밝은 획을 포함하는 표본에 오차를 집중한다. 검은 픽셀의 다수가 다른 글자에 잘못 연결된 오차를 희석하지 못하게 한다.
- 주변 16개 위치에서 길이 1 이상~8 미만의 움직임 후보를 찾고, 그 위치의 역방향 흐름과 일치해야 한다. 원본 글자 영역의 오차가 10 미만이면서 기존의 40% 미만으로 감소할 때만 채택한다.
- 실제로 빠르게 스크롤하는 글자를 단지 작은 이동이 있다는 이유로 늦추지 않는다. 고정 그래픽은 이 교정에서 제외하고 기존 stationary layer가 처리한다. 새 마스크·세션·동기화·프레임 반복은 추가하지 않는다.

완전히 일반적인 OCR이나 크레딧 인식기가 아니다. 밝은 배경·유색 글자·너무 빠른 스크롤·신뢰할 만한 주변 움직임이 없는 경우에는 교정을 적용하지 않을 수 있다. 장면명·파일명·시간에 따라 동작하는 분기는 없다.

## 검사

RTX 5090 / 드라이버 617.42. GPU 완료까지의 처리 시간으로 디코딩·표시는 제외한다. RTX 5070의 실시간 성능이나 전체 플레이어 FPS 결과가 아니다.

- 정상 간격 크레딧 95쌍: 원본 출력과 시간은 동일, 오른쪽 영상 영역의 출력은 동일했다. 원본 반복 수는 증가하지 않았다.
- 원본에서 추정한 약 8.23픽셀 스크롤을 기준으로 밝은 획을 비교한 진단 오차는 평균 10.252→7.513이었다. 90쌍 감소, 5쌍 동일, 증가한 쌍 없음. 이는 등속 이동을 가정한 진단값이며 정답 중간 프레임 대비 화질 점수가 아니다.
