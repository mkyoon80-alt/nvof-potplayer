# 연속 탐색 대응 시험 — 2026-10-14

루팡 6기 8화에서 재생바를 천천히 끌면 영상이 앞뒤로 조금씩 재생되는 증상이다.
사용자는 NVOF를 끄면 괜찮다고 확인했다. 화면 캡처가 시간 초과되어 동일한
마우스 동작을 직접 관찰하지는 못했다. 이후 사용자가 “이제 잘되”라고
재시험 결과를 확인했으며, 아래 검증에 반영했다.

## 변경과 적용

기존 필터는 탐색 후 첫 원본을 즉시 전달하고 다음 입력부터 5배 보간을 시작한다.
반복 탐색 중에도 이 동작이 반복된다. 기존 실제 재생 로그의 해당 구간은 입력
처리 최대 시간이 약 60~81ms, 정상 재생 구간은 약 43ms였다. 이 기록만으로
화면의 역방향 움직임 자체를 입증할 수는 없다.

수정본은 flush가 끝나거나 후속 segment가 시작되면 200ms 동안 원본 시각과
길이를 그대로 전달한다. 이 기간에는 보간 끝점을 쌓지 않는다. 탐색이 반복되면
200ms를 다시 세며, 종료 후 새 원본 쌍에서 보간을 재개한다. 최초 재생은
기존 동작을 유지한다. 트레이드오프는 탐색 직후 최대 약 0.2초 동안 원본
프레임률로 표시된다는 것이다. 화질 계산과 튜닝 프리셋은 변경하지 않았다.

`bin/NvofPotPlayer.ax`에 적용했다. 기존 프로세스의 로드 상태와 무관하게
새 파일을 확실히 사용하려면 팟플레이어를 완전히 종료하고 다시 실행한다.
플레이어 쪽에서 껐던 NVOF 필터도 다시 활성화해야 한다.

- 수정본 SHA256: `b416dced95eecc1f4fb2396b0b054e8265ae5b30a69923bee5cfcf20da794619`
- 이전 파일: `build/scrub-preview-20261014/baseline/NvofPotPlayer.ax`
- `NvofPotPlayer.ini`, `NvofTuning.ini` 해시 불변

## 검증

- 2026-10-14 사용자 확인: “이제 잘되.” 이후 해상도별 설정 요청으로 진행했다.

- 기존 바이너리는 새 연속 탐색 검사에서 조기 보간 시작 조건에 실패했다.
  이는 기존 정책 확인용이며, 사용자 화면의 앞뒤 움직임을 재현한 것은 아니다.
- 수정본은 NV12 GPU 입력, CPU 입력의 GPU 출력, P010 HDR 입력에서 통과했다.
  각 검사에서 전진·후진·0초 재탐색의 원본 15장, 음수 preroll 차단,
  안정화 후 보간 복귀, 복귀 시 시간 중복·틈 없음, HDR 메타데이터를 확인했다.
- 일반 23.976 → 119.88 출력 시각, EOS, 미지정 종료 시각 검사 통과.
- 파이프라인·프레임률·시각 관련 기존 CTest 7개 통과.
- 첫 수정본 실행에서 기존 장면 통계 GPU 읽기가 한 번 시간 초과되었다.
  탐색 검사 이전의 일반 재생 구간에서 발생했고, 동일 바이너리 재실행과
  이후 4개 검사는 통과했다. 이 건을 탐색 수정으로 해결했다고 주장하지 않는다.

재현 명령은 `directshow_gpu_smoke <filter.ax> --scrub-preview`이다.
CPU 경로는 뒤에 `24000 1001 120000 1001 cpu selected`, HDR 경로는
`24000 1001 120000 1001 mf selected hdr10`을 붙인다.
실행 시 테스트용 LOCALAPPDATA와 NVOF_TUNING_DIR를 별도로 지정한다.
원본 영상 복사나 대용량 프레임 추출 없이 작은 바이너리와 로그만 보관했다.
