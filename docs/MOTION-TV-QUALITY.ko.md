# TV 동작 시험 영상의 반복 무늬·할로 개선 검증

> 후속 기록: 이후 사용자가 기존 장면의 작은 화질 손해를 허용하는 기준을 지정했다. 아래는 당시의 실험 기록이며, 이후에는 여러 영상을 함께 평가해 공통 수치를 선택했다. 현재 채택 범위와 남은 한계는 [v0.4.9 변경 내역](../RELEASE.md), 실험용 화질 조정 방법은 [튜닝 안내](TUNING.md)를 참고한다.

작성일: 2026-10-13. 비교 기준은 v0.4.8의 기존 보간 셰이더입니다. 사용자가 정정한 구분대로 **1번은 반복 무늬**, **2번은 움직이는 인물 주변의 할로**를 조사했습니다.

**결과: 1번에 대한 제한적인 보정을 개발 소스에 반영했습니다. 2번 할로는 아직 해결하지 못했습니다.** 할로 실험 후보는 배경을 개선했지만 전경 디테일 회귀 기준을 넘어서 반영하지 않았습니다. 두 문제가 모두 해결됐거나 설치본에 적용됐다는 의미는 아닙니다.

|---|---|---|

각 선택 구간에서 연속된 원본 31프레임을 추출했습니다. 짝수 프레임 16장을 입력하고 숨겨 둔 홀수 원본 15장을 복원 결과와 비교했습니다. 아래 MSE는 이 15장의 **휘도 오차 평균**이며 낮을수록 좋습니다. 유효 화면은 바깥쪽 24픽셀(좌우)·16픽셀(상하)을 제외했습니다. 구간별 관심 영역도 따로 측정했습니다.

이는 약 15→30fps의 복원 시험입니다. 실제 약 30→120fps 보간은 별도로 실행하며, 그 중간 시점에는 정답 촬영 프레임이 없으므로 비교 영상은 관찰 자료입니다. 짧은 선택 구간의 결과를 전체 영상이나 모든 장면의 개선율로 일반화하지 않았습니다.

원본 MP4는 수정하지 않았습니다. 추출 영상·원시 프레임·실험 실행 파일·캡처·로그는 Git에서 제외된 `build/motion-tv-20261013/`에 보관했습니다.

## 1번: 반복 무늬 보정

채택한 보정은 실험명 `pattern6`입니다. 추가 보정은 **빠르게 이동하는 세로 반복 구조**로 한정했습니다.

기존 로직은 앞뒤 움직임이 서로 맞으면 더 짧은 움직임을 선택할 수 있었습니다. 그러나 반복 무늬에서는 양방향 모두 다른 반복 위치를 가리킬 수 있습니다. 새 로직은 원본 자체의 반복 여부, 촘촘한 작은 영역의 일치, 세로 방향으로 긴 영상 영역의 오차, 양쪽에서 얻은 움직임의 합의를 함께 확인합니다. 기존의 작은 움직임·글자·가는 선 보정은 유지합니다.

더 넓게 적용했던 초기 후보는 실제 열차 구간에서 약 2.6% 개선됐지만, 느리게 움직이는 글자 모양 선의 오차가 증가했습니다. 이 후보는 채택하지 않았습니다. 최종적으로 범위를 좁힌 뒤의 개선 폭은 다음과 같습니다.

## 2번: 할로 보정 검증

**미해결이며, 할로용 추가 보정은 소스·설치본에 반영하지 않았습니다.** 배경 움직임을 복구하는 것과 인물의 윤곽·디테일을 보존하는 것을 별도 지표로 평가했습니다. 전체 화면 오차가 낮아져도 전경 디테일 회귀 기준을 넘은 후보는 채택하지 않았습니다.

확인한 원인은 두 가지입니다. 가려지는 배경에 인물의 움직임이 잘못 배정되는 경우가 있고, 이를 수정한 뒤에도 흐름 격자의 보간 과정에서 배경과 전경 값이 섞이거나 역좌표가 잘못된 표면을 선택할 수 있습니다. 단순히 배경 벡터를 0에 가깝게 만드는 후보는 배경 오차를 낮추면서 인물 가장자리를 손상시켜 기각했습니다.

빠르게 움직이는 무늬 있는 전경에 한정하고, 같은 움직임에 속한 격자값끼리 보간하는 마지막 후보 `edge5`도 검사했습니다. 실제 영상의 복원 오차는 감소했습니다.

| 실제 2번 영상 구간 | 기존 MSE | 마지막 실험 MSE | 감소율 |
|---|---:|---:|---:|
| 빠른 움직임, 2초부터 | 67.678 | 65.924 | 2.59% |
| 느린 움직임, 12초부터 | 62.735 | 62.258 | 0.76% |
| 중간 속도, 16초부터 | 65.784 | 64.322 | 2.22% |

그러나 별도의 빠른 미세무늬 전경 시험(57픽셀/입력 간격, ×2)에서는 보이는 배경 MSE가 65.499→51.968로 감소하는 동안 **전경 디테일 MSE가 53.348→56.243, 약 5.43% 증가**했습니다. ×5에서는 전경 MSE가 72.391→74.555로 약 2.99% 증가했습니다. ×2 결과가 미리 정한 회귀 기준을 넘었으므로 기각했습니다. 기준을 완화해서 통과로 처리하지 않았습니다.

실제 빠른 구간의 약 30→120fps 시험에서는 원본 31프레임을 보존하고 124프레임을 출력했으며, 프레임 유지·장면 전환·동일 프레임 생략은 없었습니다. 그래도 이 사실만으로 인물 디테일 문제까지 해결됐다고 볼 수 없습니다. 비교 영상은 **미채택 실험 결과**로만 제공합니다. 후속 작업에는 단순 배경 벡터 수정뿐 아니라 겹치는 전경·배경 중 어느 표면을 보여줄지 결정하는 과정의 보강이 필요합니다.

## 회귀 검사와 정밀도

`pattern6`의 별도 움직임 품질 검사 32개(8장면, 2·3·4·5배 보간)는 모두 통과했고, 각 MSE는 기준 실행보다 증가하지 않았습니다. 고정 곡선, 움직이는 가는 선, 반복 글자, 좁은 물체, 다른 속도의 도형과 중간 시점 위치를 포함합니다.

새 독립 정답 시험은 15장면, 2·5배 보간의 총 30개 조합입니다. 전체 화면·경계·보이는 배경·전경을 따로 측정하며, `기존 MSE×1.03+0.01`을 넘는 항목을 회귀로 처리합니다. `pattern6`은 30개 모두 통과했습니다. 원본 프레임은 정확히 보존됐고, 출력 타임스탬프와 프레임 유지·장면 전환 판단은 기준과 같았습니다. 기존 가림·가는 선 정답 시험 16개도 통과했으며 모든 측정 MSE가 기준과 정확히 같았습니다.

전체 빌드의 CTest 19개와 추가 네이티브 검사 4개도 통과했습니다. P010 검사는 1024개 코드값, Y/UV, 크롭, 디코더 자원 재사용, 탐색, 대기/비대기 경로 및 4K ×10 결과의 일치를 포함합니다. CPU NV12 전달 검사도 통과했습니다. 이번 두 원본은 8bit이므로 이 결과를 두 파일로 HDR 화질까지 검증했다는 뜻으로 해석하면 안 됩니다.

기존 실제 영상 6개에서 엔진별 257쌍을 비교했습니다. 원본, 타이밍, 장면 전환·프레임 유지 판단을 보존했습니다. 조준선·좁은 틈·머리카락·애니메이션의 측정 관심 영역은 기준과 정확히 같았습니다. 별도 실사 홀드아웃의 MSE는 95.0940→95.0956으로 사실상 같았으며, 개선으로 계산하지 않았습니다.

## 처리 비용과 비교 자료

RTX 5090에서 이미 디코딩·업로드한 입력을 사용했습니다. 입력 쌍마다 내부 복사·흐름 추정·중간 프레임 생성 후 **GPU 완료까지 기다린 시간**을 측정했습니다. 파일 디코딩·읽기·출력 저장·화면 표시는 제외했습니다. 실행당 준비 8쌍 이후 64쌍을 측정하고, 기존→후보→후보→기존 순서로 실행했습니다. 아래 평균은 엔진별 두 실행의 평균이며, 95백분위는 두 실행의 범위입니다.

| 입력·보간 배수 | 기존 평균 ms/쌍 | 채택 보정 평균 ms/쌍 | 채택 보정 95백분위 ms/쌍 |
|---|---:|---:|---:|
| 실제 화물열차 1080p ×4 | 4.627 | 4.530 | 4.934–5.031 |
| 실제 그네 인물 1080p ×4 | 4.392 | 4.367 | 4.842–4.898 |
| 합성 영상 1080p ×2 | 3.345 | 3.285 | 5.955–6.455 |
| 합성 영상 1080p ×5 | 4.014 | 3.997 | 6.804–6.950 |
| 합성 영상 4K ×2 | 4.248 | 4.379 | 6.883–7.200 |
| 합성 영상 4K ×5 | 5.779 | 5.678 | 8.431–8.978 |

작은 차이가 섞여 있으므로 속도 향상으로 주장하지 않습니다. 짧은 단독 엔진 측정이며, 팟플레이어 전체 재생 경로의 지속 성능을 보증하지 않습니다. 이 표는 채택한 반복 무늬 보정의 수치이며, 기각한 할로 후보의 성능표가 아닙니다.

로컬 비교 영상은 왼쪽이 기존 버전, 오른쪽이 해당 보정이며 4배 느리게 재생됩니다. 원본 31프레임으로 만든 4배 보간 결과에서 마지막 패딩 그룹을 제외한 120프레임을 사용했습니다. 정량 평가는 압축 전 원시 프레임으로 수행했습니다.

- 1번 반복 무늬 비교 — 채택한 개발 보정: 로컬 실험 자료 `freight-pattern6-before-after.mp4`
- 2번 할로 비교 — 미채택 실험: 로컬 실험 자료 `swing-fast-edge5-before-after.mp4`

## 재현

플레이어와 다른 GPU 작업을 닫은 뒤 실행합니다. 도구는 매 실행 전 프로세스와 GPU 작업을 확인하며, 출력은 새 `build/` 하위 폴더로 제한합니다. 이번 검증은 Python 3.10과 NumPy를 사용했습니다.

```powershell
python tools/compare-motion-patterns.py `
  --baseline build/engine-research-20261013/baseline/Release/video_x2_repro.exe `
  --candidate build/motion-tv-20261013/accepted/Release/video_x2_repro.exe `
  --output build/motion-pattern-review-new

python tools/compare-occlusion.py `
  --baseline build/engine-research-20261013/baseline/Release/video_x2_repro.exe `
  --candidate build/motion-tv-20261013/accepted/Release/video_x2_repro.exe `
  --output build/motion-occlusion-review-new
```

설치본·INI·GPU 설정은 변경하지 않았습니다. 개발 빌드의 검증 결과를 기록한 문서이며, 새 릴리스 배포나 팟플레이어 적용 완료를 뜻하지 않습니다.
